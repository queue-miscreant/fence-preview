INTRODUCTION                                            *fence-preview-introduction*

A markdown preview extension for displaying images and rich content.

Markdown content is great for creating rich content which can also be used to
generate HTML for the web. It has found use in note-taking software such as
[Obsidian](https://obsidian.md/) and the Vim community's own
[vimwiki](https://github.com/vimwiki/vimwiki).

Since native vimwiki is already a quite nice environment, this
plugin adds an independent layer of functionality to markdown files.

The return of [Sixel](https://en.wikipedia.org/wiki/Sixel) content in terminals
has made it popular to display images in the terminal in newer applications.
Neovim does not support support sixel content natively, but this plugin's
sister plugin (and dependency) enables this functionality. See
[nvim-image-extmarks](https://github.com/queue-miscreant/nvim-image-extmarks)
for more information.


FENCES                                                  *fence-preview-fences*

Sometimes it would be nice to add some typeset content to some
notes. Instead of trying to draw it out as ASCII art, this plugin allows you
to write it out as a LaTeX snippet and render it as an image.

One of Vimwiki's nice features is that it can dynamically load syntax
highlights for content between pairs of ``` (termed "fences") based on the
|filetype| specified. For example: >

  ```latex
  \int 2xdx = x^2 + C
  ```

will use LaTeX highlights. Buying into tagging content like this makes it
easy to associate it with a way to "run" it.

That's where this plugin comes in. Rather than just having a block of LaTeX
in your notes, it displays as an image displayed inside Neovim.
See |fence-preview-#latex| for more information about this one specifically.


FENCE OPTIONS                                           *fence-preview-fence-options*
                                                        *fence_option*

Adding things to fence boundaries tends to mess with Vimwiki. The top fence
can accept a |filetype|, but adding anything onto it will load the wrong
syntax for the fence content. Conversely, adding things to the bottom fence
typically causes syntax highlighting failures on buffer contents after the
bottom.

Therefore, the first line of fenced content is interpreted specially.
The plugin interprets this line as extra options if it starts with
non-alphanumeric content followed by a comma-separated list of strings, which
may have (similar to comma-separated XML parameters)

{height}

By default, content is rendered using the same number of lines
occupied by the fence. `height` changes this to the number of lines specified.

For example,
>
  ```latex
  % height=5
  \int 2xdx = x^2 + C
  ```

Will render with 5 rather than 4 lines.
Note that rendering a taller image than the fence only works properly on
Neovim 0.10+. (TODO)

{as}

For certain plugins, interpret the "output" of the content as the input to
another pipeline.

PIPELINES                                               *fence-preview-pipelines*

Assuming data in the buffer is a "source", we'd like to pass it through
(possibly multiple) "compilation" steps before we can display it back to the
user. While UNIX pipes should enable you to chain together these programs,
there are problems with this approach.

For example, LaTeX installations don't output raster graphics and can't
output the rendered file (usually a DVI or PDF) to standard output. This
combination means that overcoming the first can't be done by piping it
into another program. Additionally, errors in one part (running `latex`) and
errors in the next (converting the DVI to something that can be displayed)
are hard to deal with.

To this end, this plugin uses pipelines to wrap lists of instructions (|Lua|
functions to accomplish something similar.

Pipelines can be associated to both the filetype of a fence and the extension of
an inline preview.

                                                        *fence-preview-default-pipelines*
The plugin provides a few default pipelines.


LATEX                                                   *fence-preview-#latex*
                                                        *fence-preview-.tex*

The LaTeX pipeline consists of the following stages:

  1. Write the fenced content to a temporary file
  3. Run `latex` on the file from step 1, generating a DVI file
  3. Run `dvisvgm` on the on the file from step 2, generating an SVG file
  4. Rasterize the file from step 3 using ImageMagick
  5. Display the raster image as an image extmark

All stages are cached using the hash of the buffer content so that each stage
can be skipped if the target file already exists.

The first stage is skipped if the content comes from a preview with extension
`.tex` rather than a fence.


MATH                                                    *fence-preview-#math*

The math pipeline is similar to the LaTeX one, but implicitly appends a
preamble to get into math mode immediately. It also automatically imports the
packages `amsmath`, `amsfonts`, `amsthm`, and `xcolor`.

Math content is rendered as white-on-black if the |'background'| option is set
to "dark". Otherwise, content is rendered as black-on white.

It includes some extra configuration options:

{math_start}
    A string containing the LaTeX preamble. This value gets prepended to the
    buffer content before it is written to a `.tex` file.

    It may contain two format specifiers (`%s`). The first is used with
    `extra_preamble` and the second is used with `extra_document` (see below).

    Note that the default value of this string accomplishes the imports above
    and produces output which tends to render nicely as images. Change it at
    your own risk.

{math_end}
    A string which terminates the commands used in the LaTeX preamble.

{extra_packages}
    A list of strings containing additional package imports.

{extra_preamble}
    A string with additional LaTeX content to add immediately before
    `\begin{document}`.

{extra_document}
    A string with additional LaTeX content to add immediately after
    `\begin{document}`.

{force_mode}
    Forces content to render as if 'background' option was set to the
    string specified.


GNUPLOT                                                 *fence-preview-#gnuplot*
                                                        *fence-preview-.plt*

The gnuplot pipeline renders a gnuplot plot as an image.

Similarly to math, gnuplot is invoked with a preamble consisting of:
>
    set output '...'
    set terminal png

where ... is the temporary output filename.

An additional stage is invoked if the content comes from a preview with
extension `.plt` rather than a fence.


PYTHON                                                  *fence-preview-#python*

The Python pipeline runs the fenced code in the current default Python
interpreter.

By default, the output will be shown as text. Adding {image} as a |fence_option|
will attempt to display the image whose filename is output by the program.

Similarly, the {as} fence option can be used with "latex" or "math" to chain
into their respective pipelines.

PIPELINE NAMES                                          *fence-preview-pipeline-names*

Each defined pipeline is associated to an internal name. The following
pipelines should always exist.


                                                        *fence-preview-highlights*
OUTPUT

"display"
    Interpret the input as a filepath. If the file exists and is an image
    (TODO), display it as an image extmark.

"text"
    Interpret the input as text. Create an extmark containing the text
    below the file content.
    To change how this displays, set the highlight |FencePreviewText|.

"error"
    Interpret the input as text. Create an extmark containing the text
    next to the file content which displays as an error.
    To change how this displays, set the highlight |FencePreviewError|.


FENCE FILETYPES

Pipelines associated to a filetype begin with `#`. For example, the pipeline
which gets run on LaTeX fences is named "#latex".


PREVEIEW EXTENSIONS

Pipelines associated to the extension of a preview begin with `.` (the dot).
For example, the pipeline which gets run on previews with the extension `.tex`
is named ".tex".

PIPELINE STAGES                                         *fence-preview-pipeline-stages*

Pipelines are composed of a list of stages -- Lua functions with a particular
signature.

                                                        *fence-preview-synchronous-stage*
At their simplest, stages have the following signature:

    {input}: pipeline_input
        The input to the pipeline. This is a table consisting of two entries:

        "node", a representation of the data in the buffer
        "previous", the output of the previous pipeline stage

    {@return}: any, string?
        The first return value is the value of the next stage's "input.previous".
        Returning `nil` will not engage the next stage.

        The second value can be left absent or set to `nil` to proceed to the next
        stage of the pipeline.
        Alternatively, it may be a string containing the name of another pipeline
        (see |fence-preview-pipeline-names|). This will skip all remaining stages
        from the current pipeline.

                                                        *fence-preview-asynchronous-stage*
However, when working with |uv| and external process, one does not have the
luxury of synchronous callbacks.
Asynchronous stages can also be defined using the signature:

    {input}: pipeline_input
        The same as above.

    {callback}: fun(ret: any, maybe_defer?: string|nil)
        Asynchronous callback for working with uv (see also |lua-loop|).
        The arguments to the function are the same as the ones in the return
        type for synchronous stages.

    {error_callback}: fun(msg: string)
        Asynchronous error callback for working with uv.
        This will be interpreted similarly to Lua's builtin `error` in
        synchronous pipelines.
